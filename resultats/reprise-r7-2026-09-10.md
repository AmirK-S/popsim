## Lineage : réserve bloquante pour l'interprétation causale

Les API aux révisions locales déclarent Base → Instruct-SFT → Instruct-DPO → Instruct final, licence Apache 2.0. Les cartes présentent le final comme RLVR. Mais le rapport officiel précise :

- **§5.2.2 : Instruct-SFT démarre depuis Think-SFT**, donc Base → Instruct-SFT n'est pas une transition SFT unique.
- **§5.4.1 : RL essayé depuis deux candidats DPO**, puis choix du checkpoint final. Le rattachement exact du final publié au DPO publié n'est pas démontré par cet audit.

Sources : [carte SFT](https://huggingface.co/allenai/Olmo-3-7B-Instruct-SFT/raw/main/README.md), [carte DPO](https://huggingface.co/allenai/Olmo-3-7B-Instruct-DPO/raw/main/README.md), [API finale figée](https://huggingface.co/api/models/allenai/Olmo-3-7B-Instruct/revision/6e5971d9eba42665f5bd5a0fcf047f299ce1dccc?blobs=true), [rapport officiel, §5](https://arxiv.org/html/2512.13961v1#S5). Consultés le 10 septembre 2026 ; revue arrêtée ici.

**Conclusion : famille commune et ascendance déclarée, pas quatre checkpoints prouvés directement appariés.** Même nombre de paramètres et tailles égales ne prouvent pas cet appariement. Il manque la correspondance run d'entraînement / checkpoint d'entrée / poids publiés. Garder provisoirement une comparaison descriptive de checkpoints ; suspendre toute attribution causale à une étape unique. Ne pas télécharger Think-SFT ni un candidat DPO pour combler ce manque par supposition.
